# CLAUDE.md

Orientation for Claude working on leprofit. Read this first.

## What this is

leProfit: a WoW: Forever addon (Lua, interface 16001) that ranks the crafts
that make gold. It was Leprofit until 2026-11-20. One addon with every profession's data built in. The agreed design is in
ROADMAP.md. 1.3.0 is released (2026-11-23; 1.0.0 was a core and nine modules); Blacksmithing and Mining are tested in game, most of 1.1.0 to 1.3.0's new parts not yet. The
remote is `addohm/leprofit` on GitHub, public, GPLv3; releases go to CurseForge and Wago.

Discuss each feature with the owner before building it.

## Layout

- `leProfit/`: the addon.
  - `Core.lua`: settings (per character, `leProfitCharDB` as `ns.db`; vendor
    records account-wide, `leProfitDB` as `ns.adb`), the profession registry
    (`ns.RegisterProfession`; the global `Leprofit.RegisterProfession` ignores 1.0's old
    module folders), events, slash commands
  - `Util.lua`: safe calls, `ns.Plain` (secret values), money text, item
    names/icons/sale info, counts, skill
  - `Prices.lua`: Auctionator and TSM prices, vendor prices, and Auctionator's
    price history (its internal database: every step guarded)
  - `Questie.lua`: where a pattern comes from, asked of QuestieDB's public API
    (`LibQuestieDB`, contract 3+) when it's installed: `Side` (cheap, for the
    lists) and `Lines` (names and places, only for tooltips). Optional, like
    Auctionator; nothing copied
  - `Data/<Profession>.lua`: each profession's data (no spaces: `FirstAid.lua`),
    generated by `tools/gen_data.py`, Mining's too (its `windowNames` = Mining
    or Smelting). `writs` = item made -> the Craftsman's Writ asking for it,
    gathered into `ns.writs` (the Crafts list's scroll, its tooltip line, the
    "writ" search). `specs` = a profession's paths (Armorsmith, Weaponsmith,
    the weapon masters with `parent` = Weaponsmith, the leatherworking paths,
    Gnomish/Goblin Engineer: `id` = the spell `IsPlayerSpell` checks) and
    `specOf` = recipe name -> the path it needs (its pattern's
    RequiredAbility; trainer-only ones from `learned.json`'s `requires`)
  - `Recipes.lua`: a profession's recipes (its data + what the window
    showed), one per name, known if the game says so (`IsPlayerSpell`, no
    window needed) or the window did. `Recipes.List(prof, pause)` builds the
    full list (sources: the costly part; `pause` lets `Profit.Prepare` spread
    it); `Recipes.Makers` is a separate cheap index of known recipes by product
    for make-vs-buy, so one craft's sums never build every list. Where to learn
    each: `source.kind` = known,
    free (comes with the profession), trainer, pattern (a vendor's, for gold),
    other (a pattern no vendor sells for gold: `Profit.Bound` says if it
    binds, the game deciding when the data doesn't; `Profit.LearnCost` prices
    a tradeable one at the auction house) or unknown. Patterns carry where to
    get them (`Recipes.WhereLines`: rep, sellers, quests, drops) and `side`
    when only one side can get them (`Profit.OtherSideOnly`: never listed).
    `rec.spec` = the path a recipe needs (`specOf`, or a trainer's record);
    `Profit.OtherSpecOnly` = a path the character can't have (it picked a
    sibling, or the path it's within is closed): never listed. The Crafts
    tab's Specialization dropdown is `ns.db.specFilter[prof]`, read through
    `Profit.SpecFilter` (a closed path's pick counts as all)
  - `Profit.lua`: the sums: make-vs-buy, sale value after the cut, profit,
    payback, flags, the filtered and sorted rows, shopping for n crafts. Each
    craft's sums are cached until `ns.sumsVersion` changes (`ns.SumsChanged`:
    data, prices, settings, items loaded; `ns.DataChanged` bumps it too), and
    `Profit.Prepare` works uncached ones out `Profit.BUDGET` ms per frame
    before the Crafts list draws (no frame does it all: the lag-spike fix)
  - `Shopping.lua`: the shopping list (ns.db.plan), its combined materials,
    and Send to Auctionator
  - `Debug.lua`: `/leprofit debug [item]`, a plain-text report (setup,
    settings, price addons, timings; for a craft every price it could use via
    `Prices.Detail`, the choice, the sums, `Profit.LeftOut`'s verdict) shown in
    `UI/Copy.lua`'s select-all window. Keep it in step when the sums change:
    it's how the owner shares discrepancies
  - `Recorder.lua`: reads the profession window while it's open (between
    TRADE_SKILL_SHOW and TRADE_SKILL_CLOSE: the list-update event also fires with
    it closed), vendors and
    trainers (costs into `ns.adb.training`, with `requires` = the path a
    trainer recipe needs, when the trainer names one), marks recipes learned
    at trainers. leProfit never opens the profession window itself
  - `UI/`: `Widgets.lua`, `Window.lua`, `Minimap.lua` (from leboof), `Confirm.lua`
    (the confirmation dialog), `Copy.lua` (text to copy out), `Crafts.lua`,
    `Shopping.lua` and `Options.lua` (the tabs)
- `tests/`: `run_tests.py` (syntax, TOCs, globals, then `smoke.lua` against
  the fake client `wowmock.lua`)
- `tools/`: `fetch_sources.py` (downloads Forever's game data tables from
  wago.tools and Efficient Games' player-recorded vendors, trainers, loot,
  quests and names into `.source/`, skipping unchanged files by EG's index),
  `gen_data.py` (writes the profession data from them and `learned.json`),
  `learned.json` (what the game data lacks: trainer costs, pattern sellers,
  vendor prices, a few item names, the camp and home items; hand-editable),
  `update_data.py` with `update_data.cmd` (the owner's interactive refresh:
  pull, download, add the records from the WTF saved files, rebuild, test,
  commit/push/install; revtunnel-style prompts),
  `install_forever.cmd` (Windows install), `make_release.py` (release zip).
  The data tools use only Python's standard library; `run_tests.py` also
  checks `update_data.py`'s SavedVariables reader and merge.
- `TESTING.md`: the in-game checklist
- `LISTING.md`: the CurseForge and Wago page text and release notes
- `art/`: `make_logo.py` draws the icons, the banner and `leProfit/Media/Icon.tga`
  (the in-game icon); the PNGs it makes
- `release/`: the release zips, one per version
- The standard docs, `LICENSE` (GNU GPLv3), and this file.
- `.source/` (git-ignored): what `tools/fetch_sources.py` downloads (`game/`
  CSVs, `eg/` JSON, `BUILD`). An old copied data file may sit there too: it's
  unused since 2026-11-22.

## Workflow

1. Start from the latest: pull before changing anything.
2. Make the change with tests.
3. **Update the docs in the same commit.** Every change updates the docs it
   affects:
   - README.md: setup and usage
   - CHANGELOG.md: an entry under *Unreleased*
   - DEPLOY.md: when deploying or running it live changes
   - SECURITY.md: when secrets, access or permissions change
   - ROADMAP.md: when something on it is done, or new plans are made
   - this file: when the layout, workflow or conventions change
4. Run the checks: `.venv/bin/python tests/run_tests.py` (set up with
   `python3 -m venv .venv && .venv/bin/pip install lupa`), then commit.
   Push when asked; say "Pushed: <commit>" after each push.

## Conventions

- Lua for WoW: Forever (Classic content, modern client, Midnight addon
  limits: guard secret values with `ns.Plain`).
- The UI follows leboof's look (`addohm/leboof`, `Leboof/UI/`).
- Settings are per character.
- The name is written leProfit: in game, in the docs, and in the folder, TOC,
  globals and zips. The repo, the listing slug and `/leprofit` stay lowercase.
  Old spellings are kept only for upgrades: the no-op `Leprofit` global (1.0's
  modules), `LeprofitCharDB`/`LeprofitDB` (moved over once at login) and the
  `Leprofit_<Profession>` folders the install script deletes.
- Show all lists everything a character could get; only what's unobtainable
  for it (the other side's recipes, and another specialization's once it has
  picked its path) is never listed, and every learnable
  recipe's tooltip says where to get it (the owner's rule, 2026-11-22). The
  side is black and white: if every known source is Horde, an Alliance
  character doesn't see it. A vendor's side comes only from a record of that
  vendor (QuestieDB, Efficient Games, leProfit's own); unknown counts for both.
  The trade camps' Merchant's Favor plans are both sides' (`gen_data.only_side`,
  `Recipes.SideOf`). Don't fill gaps from memory: accurate data or nothing.
- When the Crafts list gets dense, put per-craft detail in the row tooltip;
  add a column only for things worth sorting or scanning by (the owner's
  rule).
- Tabs for indentation; a comment at the top of each file says what it's
  for, and comments explain why, in plain words (leboof's style).
- A new profession: add it to `PROFESSIONS` in `tools/gen_data.py`, run it,
  list `Data\<Profession>.lua` in `leProfit.toc` (the tests check every file
  is listed), add it to the tests' list, run them, and update README and
  TESTING.
- Don't bring back separate profession addons: the data is small (2.7 MB in
  memory for all nine), so it's one addon (the owner's call, 2026-11-20).
- A few recipe IDs are in several professions' data (Forever's camp and home
  items, Synthetic Gordok Ogre Suit); that's kept on purpose. The camp items
  are on gathering skill lines in the game data, so they're listed in
  `learned.json`'s `extraRecipes`. Rogue poisons (skill line 40) aren't a
  profession here.
- Performance: nothing heavy per frame. Redraws reuse cached sums; new work
  goes through `Profit.Prepare`; costly reads (price history, QuestieDB names,
  item details) happen only when shown, and once. Wrap new event handlers and
  timers in `ns.Timed(name, fn, ...)` so `/leprofit perf` can name them.
- Make-vs-buy looks at the recipes this character knows in every
  profession (smelting feeds Blacksmithing); "Smelt ..." recipes are only ever
  recorded under Mining.
- Batch files need CRLF (`.gitattributes`).

## Don't

- Commit secrets (`.env`, keys, tokens).
- Commit `.source/`, or name where 1.0's data came from in anything committed:
  code, data, docs or commit messages. (The new sources, Forever's game data and
  Efficient Games, are named and credited: CC BY 4.0 needs it.)
- Show the version or build in the addon's window: chat only (`/leprofit help`).
